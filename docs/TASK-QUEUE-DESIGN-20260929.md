# 任务队列设计（2026-09-29）

> 主人："让大模型决定是对的。但是任务队列你好好设计一下吧。"
> 前置审计：`modpack-study/_work/task-queue-audit-20260928.md`（C1–C11：现在没有队列，新动作一律顶掉旧的，没做完的只写进一句提示）。
> 主人已确认（2026-09-29）：①主人交代的事**自动进队列**；②主人交代的事**没有过期时间**；③重启后没做完的事保留、醒来第一轮提醒她。
> 本文在那份审计的"方案 B（可暂停恢复的任务栈）"基础上，按主人定的原则改：**决定权在大模型，队列只负责"记住"和"摆到她眼前"。**

---

## 一、原则

1. **大模型决定做什么，队列不替她做决定。** 队列不自己执行步骤、不自动插"去砍树"这种子任务。缺材料时是她自己决定"先去砍树"，队列只负责记住"砍完树要回来做木镐"。
2. **不丢事。** 任何一件没做完的事（被打断、被本能抢走、被新指令插队）都留在队列里，直到**做完 / 她明确放弃 / 过期**，三者之一。过期和放弃都要说出来，不许静默消失。
3. **不乱顶。** 只有"动身体、换一件事"的动作才会打断手上的事；看一眼、查背包、查配方、说话这类**不动身体的**永远不打断。
4. **保命不受队列约束。** 本能（战斗 / 憋气 / 危险方块）照旧直接抢身体；队列只是在它结束后把被打断的事重新摆出来。
5. **身体层不排队**（`body-command-lock.js` 的既定设计，审计 C6）。队列在意识层（mind），身体层继续"一次一条命令、忙就明确 busy"。

## 二、分层

```
本能层 (instinct)       保命抢占，最高权限，不认识队列 —— 照旧
   ↑ reject / abort
身体锁 (bridge)         单条身体命令互斥，不排队 —— 照旧
   ↑ 一次工具调用
任务层 (mind/tasks)     ★新增：任务对象、队列、暂停 / 恢复、过期、持久化
   ↑ 工具（task_*）+ 调度提醒
意识层 (mind/think)     大模型：决定开始 / 插队 / 排后面 / 放弃 / 接着做
```

## 三、任务对象

```js
{
  id: 17,                     // 单调递增
  title: '做一把铁镐',         // 人话，给她自己看、也给主人看
  source: 'player' | 'self' | 'plan',   // 谁要的：主人交代 / 她自己想做 / 长期计划那一步
  askedBy: 'Ka_sum1' | null,  // 主人交代时是谁
  said: '帮我做把铁镐',        // 主人原话（source=player 时）
  status: 'queued' | 'running' | 'paused' | 'done' | 'failed' | 'dropped' | 'expired',
  pausedWhy: null | 'player' | 'instinct' | 'self',   // 为什么停下（被主人插队 / 被本能抢 / 她自己换了）
  parent: null | 16,          // 为了哪件事而做（"先砍树"是为了"做木镐"）
  steps: [{ tool, args }],    // 当前这一段的动作（沿用现在 W.job 的 steps）
  i: 3,                       // 做到第几步（断点，只用于"告诉她做到哪了"，恢复时她自己决定怎么接）
  progress: '已经做了木棍，还缺 3 个铁锭',   // 她自己写的进度备注（task_note 工具）
  planStep: null | 2,         // 属于长期计划第几步（source=plan）
  createdAt, updatedAt,
  ttlMs,                      // 过期时间：player **不过期**（主人 2026-09-29）、self 20 分钟、plan 跟着计划走（不过期）
  interruptions: 0,           // 被打断几次（≥ 3 就提醒她"这件老被打断，要不要先放下"）
}
```

- `W.job` 保留（审计 C1：改名风险大），语义变成"**当前 running 那个任务的执行游标**"。`W.job.taskId` 指回任务对象。
- 存放：新文件 `src/mind/mind/tasks.js`（纯函数 + 状态，**队列只此一份**，挂在 `W.tasks`），持久化到 `memory/tasks.json`（原子写；重启后 `running` 一律改成 `paused(restart)`，过期的直接标 `expired` 并在醒来第一轮告诉她）。

## 四、大模型的工具（她用这些管理自己的事）

| 工具 | 作用 |
|---|---|
| `task_add({ title, when: 'now' \| 'next' \| 'later', parent?, why? })` | 记一件事。`now` = 现在就做（当前的变 `paused`）；`next` = 手上这件做完就做；`later` = 排到后面。`parent` = 这是为了哪件事做的（缺材料时"先砍树"挂在"做木镐"下面）。 |
| `task_note({ id?, progress })` | 写一句进度（"木棍做好了，还缺铁"）。默认写当前任务。 |
| `task_done({ id?, result })` | 标记做完。**必须有证据**：最近的工具结果里有对应的成功（沿用说话闸的"诚实"判据，见 `gates.js` 的 `unbackedClaim`），没有就拒绝并告诉她缺什么证据。 |
| `task_drop({ id, why })` | 放弃一件事。主人交代的，放弃时**要跟主人说一声**（说话闸放行这一句）。 |
| `task_resume({ id })` | 接着做一件 paused / queued 的事（成为 running）。 |

- 现有的动作工具（`goto` / `craft` / `mine` …）照旧直接用。**她在没有 running 任务时直接发动作**，系统自动建一个 `source=self` 的任务包住它（标题用她这一轮的想法 / 主人原话前 30 字），这样不用每次都先 `task_add`。
- 主人交代事情（说话闸里判"交代"的 `TASK_ASK_RE`，已有）时，**系统自动建一个 `source=player` 的任务**（`queued`，title=主人原话），她这一轮决定是 `task_resume` 马上做、还是先把手上的做完。这样主人说过的事**一定进队列**，不靠她记得。

## 五、打断规则（什么会顶掉手上的事）

| 这一轮她发出的 | 手上有 running 任务时 |
|---|---|
| 只动嘴 / 只看（`say` `look_at` `look_around` `scan_blocks` `inventory` `recipe` `how_to_obtain` `home_stock` `knowledge_search` `task_*`…） | **不打断**，并行 |
| `stop`（主人叫停） | 当前任务 `paused(player)`；主人说"都别做了 / 算了"→ 队列里 player 任务全部 `dropped`（并说一声） |
| `follow` / `come_to`（主人叫她过来） | 当前 `paused(player)`，跟完 / 到了之后提醒她接着做 |
| 其他动身体的动作（`goto` `craft` `mine` `place` …） | 当前 `paused(self)` —— **不丢**，下面第六节会把它摆回来 |
| 本能抢身体 | 当前 `paused(instinct)`；本能结束后提醒她 |

- 沿用现有的 `look_at` 特例（审计 C3），扩大成"不动身体的工具一律不打断"。判"动不动身体"的名单**只此一份**（对齐 bridge 的 `PASSIVE_POSTS`）。
- 身体忙（`busy`）不算任务失败：有限次重试（审计阶段 2 已提）。

## 六、调度（队列怎么"摆到她眼前"）—— 不替她决定

1. **每一轮的上下文**里固定一段（很短，最多 5 行）：
   ```
   【手上的事】#17 做一把铁镐（主人交代，做到第 3 步：已经做了木棍，还缺 3 个铁锭）
   【排着的】#18 去砍点木头（为了 #17）· #15 把家里暗处插亮（被打断：主人叫你过来）
   ```
2. **什么时候提醒她"该接着做了"**（触发一次 think，事件里写清楚）：
   - running 的做完 / 失败了，队列里还有事 → "#17 还没做完（做到……），接着做还是先做 #18？"
   - 本能结束、`paused(instinct)` 的还在 → "刚才打完怪了，#17 还做吗？"
   - 跟随 / 过来结束 → 同上
   - 闲着（现有的 idle 触发）且队列非空 → 把最该做的那件放在提醒里
3. **排序只是建议顺序**（她可以不照）：`player` > `plan` > `self`；同类里 `paused` 先于 `queued`；有 `parent` 的子任务排在它的 parent 前面；越久的越前。
4. **子任务做完 → 自动提醒 parent**："#18 砍完了，回去做 #17 吗？" —— 这就是"缺材料时她决定先去弄，弄完能回来"的全部机制。

## 七、过期与放弃（不静默丢）

- **主人交代的（`source=player`）永远不过期**（主人 2026-09-29："玩家交代的事情没有过期时间"）—— 只有做完、或她跟主人说过之后放弃（`task_drop`），才会离开队列。
- 她自己想做的（`source=self`）`ttlMs` 到了 → 标 `expired`，下一轮上下文里告诉她一句（不用跟主人说）。
- `interruptions ≥ 3` → 提醒她"#17 被打断 3 次了，要不要先放下"——**她决定**。
- 同一件事（同 `source` + 同 `title` 或主人同一句话）**合并**，不重复建。
- 队列上限：`queued + paused` 最多 12 件，超了提醒她清理（不自动删）。

## 八、诚实

- `task_done` 必须有工具成功的证据（第四节）。说话闸的"诚实"判据同时看任务状态：说"铁镐做好了"而 #17 不是 `done` → 拦。
- 被打断时她只能说"做到 X 了，还没做 Y"，不能说做完了（审计阶段 3）。
- 主人问"你在干嘛 / 还有什么没做" → 她照【手上的事】【排着的】回答（提示词加一句）。

## 九、和现有东西的关系

| 现有 | 关系 |
|---|---|
| `plan.js` 长期计划 | 计划是清单；计划的"下一步"在她开始做时变成一个 `source=plan` 的任务（`planStep` 指回去），做完时 `plan.updateStep` 打勾。**计划本身不改**。 |
| `W.job` / `startJob` | 保留，变成"running 任务的执行游标"；`startJob` 不再无条件 `/stop` 旧任务，而是先把旧任务标 `paused`。 |
| 说话闸 `TASK_ASK_RE` / `taskDoneAllowed` | "交代"的判据复用 `TASK_ASK_RE`；"做完说一声"改成看任务状态（`done` 且 `source=player`）。 |
| 本能 | 不改；只在 mind 这边收到"被本能抢了 / 本能结束"时更新任务状态。 |

## 十、观测

- `GET :3003/mind` 返回 `tasks`（当前 + 队列 + 最近 10 件结束的）。
- `logs/mind.log` 每次状态变化一行：`📋 #17 做一把铁镐 running→paused(instinct)`。
- 自我复盘（`self-review`）记：被打断次数、过期件数、主人交代的完成率。
