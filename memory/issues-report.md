## 二、本轮最有价值的三个发现

### 1. P8 的真正根因 —— "打怪感知慢"不是慢，是分类表漏了一整类

**实战证据**（她被骷髅射到 1 点血，全程站桩挨打）：

```
[21:05:05] 💔 掉血 15.33 → 9.33
[21:05:33] 💔 掉血 14.83 → 1        ← 只剩 1 点血
[21:05:42] 💬 (danger) 呜…我血不多了，先躲一下下
[21:06:55] 💔 掉血 18 → 3.17
而位置 (-8,87,-4) 全程没变
```

**两个叠加的 bug**：
- 网桥侧：`type === 'hostile'` 漏了（只认 `'mob'`）→ `counts.hostile` **恒为 0**
- autopilot 侧：`nearestHostile` 只查 **34 个原版名字白名单**，而服上有 516 个模组

→ `flee` 分支**永远进不去**。她感知到了危险（说了台词），但**没有任何躲避动作**。

**已修**：判据改三级（`kind` → `type` → 名字白名单兜底），新增 9 条回归锁，
其中专门用 `name: 'unknown'` 覆盖真实的失败 case。

### 2. P20 —— `drops` 表缺一整维，她一直在做"没有产出的劳动"

**决定性实验**：
```
POST /mine {"blockName":"stone","count":3}
→ mined: 3        ← 世界真的变了
  invDelta: 0     ← 但背包一件都没多
```

原版规则：石头/方解石/矿石**徒手挖会破坏方块但不掉落物品**。
而 `minecraft-data` 的 `drops` 只写"掉什么"，**不写"需要什么工具"**。

数据其实一直在手里（`harvestTools` 字段从未被用过）：
```
stone      harvestTools={779,784,789,794,799,804}  ← 需要镐子
dirt/oak_log/sand/gravel/clay  harvestTools=undefined  ← 徒手就行
```

### 3. P21 —— 她其实站在**玩家的建筑**里，一直在拆它

修好 P20 后，`/scan` 的短名单**突然变了脸**：
```
acacia_stairs x67 / oak_planks x53 / acacia_fence_gate x14
stripped_oak_log x26 / lantern / stone_bricks x20
```

判据很硬：`planks`/`stairs`/`slab`/`fence`/`gate` **全部是合成产物**，
自然界不生成；而且**跨三种木材**混在一起。这是玩家建造的房子。

**这解释了之前所有怪异现象**：莫名出现的 `stick ×3`（从建筑里捡的）、
"一路向下挖 15 格 calcite"（挖的是人家地基）、挖半天零增长。

## 四、**不能解决** / 需要外部条件（3 类）

### 1. 配方问题需要服务端侧或深度协议逆向 —— **当前条件下无解**

- 独立探针实测：**不带 FML 握手直连会被服务器直接断线**（一个包都收不到）
  → 这服**必须走完整 FML 握手上线**
- 服务端声明的 37 个注册表里**有** `minecraft:recipe_serializer`（已解析出 264 条），
  **但没有** `minecraft:recipe` —— 配方数据不走注册表同步
- 它走 `forge:registry_data` 自定义 payload 或内联配方同步通道，
  而那 **202 个通道**我们只识别了少数几个

**结论**：理论上能拿到（数据确实在网络上传输过），但**需要针对 Forge 的配方同步协议做专门逆向**，
工作量与"从零逆向一个协议"相当。**不是本轮能完成的。**

### 2. "完全自主建立庇护所 + 持续发育"在无配方约束下**上限被锁死**

即使把所有工具链问题都修好，**合成不可用**意味着：

| 目标 | 无配方时能否达成 |
|---|---|
| 挖土/沙/砾石/黏土/木头 | ✅ 能（徒手可挖） |
| 盖土屋/木屋（纯放置） | ✅ 能（不需要工作台） |
| 挖石头/矿石 | ❌ 不能（**挖了也不掉落**，见 P20） |
| 做木镐/石镐 | ❌ 不能（需要合成） |
| 任何工具、武器、盔甲 | ❌ 不能 |
| 床（跳过夜晚） | ❌ 不能 |
| 熔炼、箱子、门 | ❌ 不能 |

**所以"持续发育"当前的上限是：石器时代之前**。
能活下来（土屋 + 徒手采集），但**不能真正发展**。

### 3. 多人环境的社交维度完全空白

P21 暴露出她周围有玩家建筑，而我们的判据里**没有一条问"这是谁的东西"**。

- 能识别"这是人造方块"（已做，P21）
- ❌ **不能**识别"这是谁的"（没有权限/领地数据）
- ❌ **不能**判断"我能不能动它"（没有服务器规则信息）
- ❌ **不能**与服主沟通询问

**在公共服务器上，这一维度只能靠保守策略**（不碰人造方块 + 换地方自建），
**技术上无法做到"智能判断哪些能拆"**。

## 六、方法论沉淀（比单个 bug 更重要）

本轮 21 个问题里，**教训高度集中在同几类**：

1. **"声称成功"与"世界真的变了"是两件事**（P1c、P13、P20）
   → 判据必须来自世界状态，不能来自 API 返回值。

2. **"我没有"和"我读不到"必须能区分**（P4、P8、P20、P12）
   → 三态（true/false/null）优于二态。

3. **修一个反模式时，先 grep 它在全仓出现几次**（P14）
   → 局部修复 + 全局存在 = 复发。

4. **测试数据必须覆盖真实的失败 case**（P2b、P8）
   → 否则测试在替 bug 站岗。

5. **判据修得越对，被掩盖的问题暴露得越快**（P20 → P21）
   → 修好 P20 才看见"她在拆别人房子"，这是好事不是坏事。

6. **"等结果"有两个坑：等得不够久，和"等对了"这个信号没被认出来**（P10、P12）

7. **换成"更宽松的方案"之前，先问它隐含要求了什么**（P9 → P11）
